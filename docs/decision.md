Read the blueprint, then this file, before touching anything. Add a row to the Build log and, when a plan changes, a new numbered decision here before building.

| 031 | Progression, achievements, daily seed, input (p2b-3): stars are skill only: win 1, no downs 2, no downs with at least 50 Resolve left and 40 percent perfect responses 3, loss 0. Career opens one struggle at a time; Trials open after tier 1 (in order); Sparring after the first win; Endurance after tier 2; Daily and Training always. The Daily Bout opponent is chosen from the 25 non-final struggles by a seeded pick from a 32-bit FNV-1a hash of the date key (never String.hashCode). 15 local achievements, evaluated from progress plus the bout just played. Input is synchronous (events returned from gesture calls) instead of a Stream, so tests need no async; a sideways flick of 28 px or more is a Slip, a shorter touch is a tap, two taps within 260 ms in the opening are a Combo. | 032 | Balance simulation (p2b-4): `BoutSimulator` plays whole bouts headless through the real AI, resolver and fight rules, with seeded bots (novice, average, expert) whose timing error is normal around the beat so the timing windows, stances and cards matter. Per-struggle damage reaching the player is set in `StruggleTuning` (tier values 600/450/330/160 percent with per-struggle overrides) instead of editing move sets. Bands asserted for the average bot: tier 1 85 to 99, tier 2 72 to 98, tier 3 55 to 92, tier 4 38 to 72, Still Standing 32 to 55; novices win at least 20 percent of tier 1 and at most 20 percent of tier 4; experts win at least 90 percent everywhere; stance spread at most 25 points; a starter card moves a win rate at most 30 points. The bots are my model of players, not real players: Test APK 1 and Holy's reports are what finally set difficulty, and the table is printed in the CI log of every run. Expert bots win about 97 to 100 percent of everything, so the hardest fights are not hard for a perfect player; real human variance is expected to change that. |
| 033 | Ports, storage and verses (p2c): ten small ports (storage, ads, consent, billing, notification, audio, haptics, connectivity, log, clock) with in-memory fakes in `test/fakes/fakes.dart`. Saved progress is an envelope with a format number, a SHA-256 checksum and the payload as a string (so the checksum never depends on re-encoding); migrations run n to n+1; a newer schema is read-only and never overwritten; the store keeps the previous good save as `progress.bak`, recovers from it when the main file is damaged, starts clean with a one-time notice when both are, and never throws on load. Settings fall back to defaults when unreadable. `VerseRepository` reads the bundled assets through a loader function, falls back to English for a missing language, bundle or verse, picks verses by seed, and serves each struggle's opponent-card verse (`prebout_<id>`) and each card's verse (`card_<id>`). `VerseNumberMap` holds the 15 Psalm shifts for French, Arabic and Chinese and a test compares it to `tools/scripture/alignment.json`. |
| 034 | Platform adapters A (p2d): `StorageService` writes files atomically (temp file then rename), refuses unsafe names, and when a write fails keeps the data in memory, throws a StorageError and reports `degraded` until a later write or `flushPending` succeeds; key-value strings use `SharedPreferencesAsync` behind a small backend interface. `LogService` is a rotating local log (64 KB) with a capped email export and never throws. `ConnectivityService` is a hint only (a failing plugin counts as online). `HapticsService` uses the platform pulses and obeys a Settings switch. `AudioService` addresses assets by full path (`assets/audio/<id>.wav`), clamps volume, and logs instead of throwing, so missing sound files before p7a cannot crash. `NotificationService` schedules one inexact daily reminder (no exact-alarm permission), asks for permission only when the player turns reminders on, and exposes taps and launch-from-notification for the router. `UrlService` opens only https links and a hand-encoded mailto. Native setup added for the reminder: core library desugaring and the two scheduled-notification receivers plus RECEIVE_BOOT_COMPLETED on Android, the notification delegate in the iOS AppDelegate, and https and mailto package queries. The plugin calls were written against the plugins' published sources and compiled first time, but only a device run (Test APK 1) proves the reminder actually fires. |
| 035 | Platform adapters B (p2e): `AppConfig` holds the support email, the product id `remove_ads` and the 10-minute interstitial gap; the website and flags addresses are empty until Cloudflare Pages is live, and nothing is requested while they are empty. `ConsentService` refreshes UMP on every launch, shows the form when required, and always reads the platform's saved `canRequestAds` so a failed, slow or offline refresh never overrides saved consent. The app does not set the under-age-of-consent tag: the audience is 13 and over and the game is not child-directed (open item: confirm with the AdMob audience settings). `AdService` does nothing before consent; interstitials also need ads not removed and the 10-minute gap from app start or the last ad; rewarded ads stay available after Remove Ads; every failure only means no ad. Ad unit ids are Google's sample ids, verified against Google's Android and iOS test-ads pages (the anchored adaptive banner id is used for banners); production ids replace them only when Ak supplies them. `BillingService` reads the store's own purchase state with a restore at launch, caches the last answer (an offline launch keeps a paid player ad-free; a silent store never removes a cached purchase at launch), and reports pending purchases through a stream. `FlagsService` fetches only https, within 5 seconds, at most 16 KB, caches the last good answer and falls back to it, then to defaults; website/privacy.html already discloses this request. |
| 036 | Providers A (p3a): every provider is a `ValueNotifier` over an immutable state, reaches the outside only through core ports, and applies a change at once then saves in order; a failed save sets `saveFailed` (the change still counts this session) and the next change or `retrySave` tries again. Settings load defaults if storage is unreadable. Language: the player's choice, else the phone's list (`pt_BR` and `iw` normalise), else English; only the 11 languages are accepted; Arabic and Hebrew are right-to-left. Progress carries a one-time notice for a recovered or clean-started save and goes read-only when the save is from a newer app. The loadout keeps only earned, known cards, at most three, no repeats. Ads removed is one answer (`EntitlementState.adsRemoved`); unknown counts as not removed; a second purchase action during one in progress is ignored. |
